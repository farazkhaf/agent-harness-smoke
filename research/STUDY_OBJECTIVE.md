# Study objective

Agent Harness Smoke is a designer-facing diagnostic framework for studying how coding-agent harnesses mediate software-engineering execution. The primary object of study is the **realized interaction route**: which workspace primitives a model selects, how those primitives are composed, and how navigation, transformation, recovery, requirement retention, context stewardship, verification, and completion behavior change across harness interfaces and task pressures.

Correctness anchors every trajectory against the same task contract, but the study is not organized as a product ranking or harness leaderboard. Harnesses are treated as complete execution interfaces. Observed differences are therefore configuration-level and route-level evidence, not isolated causal effects of one hidden implementation detail.

## Research questions

The current study is organized around four questions:

1. **Primitive realization.** When a task can be solved through more than one legitimate workspace interaction primitive, which primitives are actually used by each model-harness configuration?
2. **Route composition.** How are inspection, localization, editing, structured transformation, testing, and verification composed as task pressure increases from focused operations to multi-surface scenarios?
3. **Stewardship and recovery.** Where do requirement retention, context management, edit-route correction, implementation recovery, verification-probe recovery, and post-green work appear in the trajectory?
4. **Affordance uptake.** Which harness affordances are taken up, ignored, or substituted with another valid route? Availability of an affordance is not treated as evidence that the model used it.

## What the study does not claim

The current repeated cells do not estimate stable harness success probabilities, establish product rankings, or support claims that one harness is globally faster, cheaper, or more reliable. Calls, tokens, time, patch size, verifier-group outcomes, and route features are retained as descriptive evidence. Larger repeated-run samples would be required for population-level reliability or efficiency claims.

## Role of focused tasks and scenarios

Focused tasks calibrate narrow workspace pressures such as coordinated propagation, selective repeated editing, deletion, extraction, line-oriented filtering, and same-process verification. Scenarios compose several pressures into a coherent maintenance task while preserving one explicit target software state and leaving the execution route unconstrained.

This creates a progression from legible primitive pressure to realistic route composition without requiring the research to become a leaderboard.
